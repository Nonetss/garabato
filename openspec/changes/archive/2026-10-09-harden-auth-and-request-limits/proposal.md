## Why

The app is published on a public domain and keeps signing certificates and private PDFs, yet anyone can register an account, an account is protected only by its password, and nothing bounds how much memory or CPU one user can take with document operations. The oRPC handlers already cap request bodies (1 MiB, 21 MiB for uploads), but Bun itself still buffers up to its 128 MiB default on every other route, and a single user can run any number of PDF uploads, signatures, page edits and merges at once, each of them fully in memory.

## What Changes

- New `DISABLE_SIGN_UP` server variable (boolean, default `false`). When `true`, the email/password sign-up endpoint and implicit sign-up through OIDC are refused, the public `v1.authConfig.get` reports `signUpEnabled: false`, and the frontend hides the sign-up link and serves no sign-up form. Admins keep creating accounts from the admin users page. When unset or `false`, behaviour is the same as today.
- The admin seed creates the administrator through Better Auth's admin `createUser` (with the `admin` role) instead of the public sign-up, so seeding keeps working with sign-up disabled.
- Optional two-factor authentication (TOTP with backup codes) through Better Auth's `twoFactor` plugin. Each user turns it on or off from their profile; nobody is forced to. Once it is on, an email/password sign-in asks for a code from the authenticator app (or a backup code) before creating the session, with an option to trust the device for 30 days.
- **Schema change**: the `twoFactor` plugin needs a `two_factor` table and a `two_factor_enabled` column on `user`. The schema is edited in this change; the migration is generated and applied by the user.
- `Bun.serve` gets `maxRequestBodySize` of 25 MiB, an outer bound above the oRPC upload limit (21 MiB) that also covers `/api/auth/*` and every other Hono route.
- A per-user limit on heavy document operations (`v1.document.upload`, `sign`, `editPages`, `merge` and `verifySignatures`): at most 2 running at once and at most 30 started per minute per user. Calls beyond either bound are refused with `429 TOO_MANY_REQUESTS` and a Spanish message, before any PDF is parsed or decrypted. The limit is held in memory, like the single-instance cron scheduler.

## Capabilities

### New Capabilities

- `two-factor-authentication`: opt-in TOTP two-factor authentication per user, its enrolment and removal from the profile page, the second sign-in step, backup codes and trusted devices.
- `document-operation-limits`: per-user concurrency and rate limits on the heavy document procedures and the error they return.

### Modified Capabilities

- `authentication`: sign-up can be disabled by configuration, `v1.authConfig.get` reports `signUpEnabled`, the sign-in and sign-up pages follow it, and admin seeding no longer goes through public sign-up.
- `environment-configuration`: the validated server environment gains `DISABLE_SIGN_UP` (default `false`).
- `http-server`: the Bun server rejects request bodies above 25 MiB on every route.

## Impact

- **Code**: `packages/env/src/server.ts`, `.env.example` and the env scripts (`scripts/bootstrap.sh`); `packages/auth/src/index.ts` and `oauth.ts`; `packages/db/src/seed/admin.ts`; `packages/db/src/schema/auth/auth.ts`; `packages/api/src/v1/auth-config/*`, `packages/api/src/index.ts` and the document router; a new limiter in `packages/api/src/shared/`; `apps/backend/src/index.ts`; `apps/frontend` auth client, sign-in and sign-up slices, `/signup` page and the profile slice.
- **Database**: new table and column for two-factor (migration generated by the user, not by the agent).
- **API**: `v1.authConfig.get` output gains `signUpEnabled`; the five heavy document procedures can now answer `429`; Better Auth exposes the `/api/auth/two-factor/*` endpoints.
- **Behaviour without configuration**: unchanged sign-up, 2FA off for every user, normal usage well below the new limits.
- **Not covered**: 2FA applies to email/password sign-in only. SSO users rely on their identity provider's MFA, and API keys keep authenticating on their own.
