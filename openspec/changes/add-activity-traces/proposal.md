## Why

The "Firmas" page (`/signatures`) only shows signatures, because the signature record is the only action the app keeps a trail of. Importing or deleting a certificate, remembering its password, uploading, merging, editing, downloading, renaming, moving or deleting a document leave no trace a user can review, so they cannot answer "what happened to this certificate or document, and when?". The page should become "Trazas": one chronological trail of everything the user did with their documents and certificates, signatures included.

## What Changes

- New append-only trace table: every traced action writes one event (type, time, document and/or certificate, version, client IP and type-specific details such as the old and new name) in the same transaction as the action itself, so an action never commits without its trace.
- Traced actions: certificate imported, renamed, password remembered, password forgotten and deleted; document uploaded, merged, pages edited, downloaded, renamed, moved and deleted. Signatures keep their own evidence table (`document_signatures`) and show in the trail as "signed" events read from it, so every past signature appears without a backfill.
- New explicit download procedure: the existing `GET document.download` stays a safe read used by the viewer and thumbnails and is not traced; the download buttons call a new `POST` procedure that returns the same file and records the "downloaded" event.
- New `trace` API feature: a paginated trail (signatures and events merged, newest first, cursor + total) filterable by event type, certificate, text (document name or certificate alias) and date range, plus the certificate list for its filter.
- **BREAKING** The frontend page `/signatures` ("Firmas") is replaced by `/traces` ("Trazas"); `/signatures` is removed without a redirect and answers 404. The navbar entry, surface search entry and frontend feature folder are renamed accordingly. Signature rows keep today's full detail panel; the other events get a detail panel of their own.
- The `document.signatureLog` and `document.signatureLogCertificates` procedures stay as they are (public API); the frontend stops using them.
- Docs that point to `/signatures` (README, project site docs and its screenshot route) are updated to `/traces`.
- Requires a schema change (new table); the migration is generated and applied by the user.

## Capabilities

### New Capabilities

- `activity-traces`: recording trace events for certificate and document actions, listing and filtering the caller's trail (events plus signatures), and the "Trazas" page at `/traces` with its filters and detail panels.

### Modified Capabilities

- `signature-log`: the "Signatures page", "Signatures page filters" and "Signature detail" requirements are removed (the page moves to `activity-traces` as "Trazas"); the signature log API requirements stay unchanged.
- `list-filter-experience`: the scroll-to-top opt-in names the traces page instead of the signatures page.
- `document-management`: downloading a version from the UI is traced through a new explicit download procedure; the plain download read stays untraced.

## Impact

- `packages/db/src/schema/`: new `trace` schema module (table + types); migration to be generated by the user.
- `packages/api`: new `src/v1/trace/` feature (`list`, `certificates`) wired into the v1 router; a shared `recordTrace` helper and the shared client-IP helper (moved out of `document/handler.ts`) in `src/shared/`; `certificate` and `document` handlers write traces inside their transactions; new `POST document.exportVersion` procedure; tests under `packages/api/tests/`.
- `apps/frontend`: `features/signatures` becomes `features/traces`; `pages/signatures/` becomes `pages/traces/`; `lib/app-surfaces.ts`, `lib/icon-registry.ts` and the surface search sources; the download actions in `features/documents` call the traced procedure.
- Docs: `README.md`, `apps/site` docs (`first-run.md` en/es, `i18n/ui.ts`, `lib/screens.ts`); the `signatures*.webp` screenshots need retaking by the user.
