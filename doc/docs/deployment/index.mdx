Hay cuatro ficheros compose, uno por forma de ejecutar el proyecto:

<Entities type="compose-files" />

Los tres de la raíz levantan las tres imágenes de la aplicación (frontend, backend y gateway), Loki y el almacén de documentos MinIO (`pgsty/silo`, una compilación de MinIO). `compose.yml` y `compose.prod.yml` añaden además PostgreSQL (`postgres:17`). El de desarrollo no levanta base de datos: usa una PostgreSQL de fuera del proyecto ([Base de datos](../development/database.mdx)).

## Solo el gateway publica un puerto

En todos los compose, el único servicio con `ports` es el gateway. El frontend, el backend, la base de datos, Loki y MinIO solo se ven dentro de la red del stack (`expose`), y el gateway reparte las peticiones entre el backend y el frontend ([El camino de una petición](../architecture/request.mdx)).

- Una ruta pública nueva se añade en `apps/gateway/routes.caddy`, nunca publicando el puerto de otro servicio.
- Ni siquiera la consola de MinIO se publica: MinIO se administra con `mc` dentro del contenedor (`docker exec <contenedor> mc …`).
